SLA Pause Report for Jira Service Management

Which SLAs pause, which breach, and where.

Scan a service desk's last 30 days of requests and group paused and breached SLA metrics by metric, request type and status.

What it does

An SLA that pauses looks healthy on the dashboard while your customers wait. The pause is usually legitimate - waiting for the customer, waiting for a vendor - but when it happens often, at one status or one request type, it is a process problem.

SLA Pause Report reads the requests created in the last 30 days on a service desk, collects every SLA metric on them and groups the paused and breached ones by metric, request type and the status the request was in. The table filters by those columns, and the grouped view exports as CSV for a review meeting.

The SLA API does not expose a pause reason, so the report shows the request's status at scan time and claims nothing more. Scans advance on the hourly schedule, ten requests per invocation, and everything the app stores is removed on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → SLA Pause Report for Jira Service Management.

  • Scans requests from the last 30 days on a chosen service desk
  • One row per SLA metric: paused, breached, and the status it paused in
  • Groups by metric, request type and status
  • Filterable table and CSV export of the grouped view
  • Hourly scheduled scan, ten requests per invocation
  • Stored scan data removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
