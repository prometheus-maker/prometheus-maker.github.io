Required on Transition for Jira

Block a workflow transition until the fields your team needs are filled in.

A workflow validator that requires chosen fields before an issue can move, with rules managed on an admin page instead of inside the workflow editor.

What it does

Jira's built-in required fields apply to screens, not transitions. If a team needs a component or a due date before an issue goes to In Progress, the usual answer is a workflow edit - and then another edit every time the rule changes.

Required on Transition adds one validator to a transition. Which fields are required lives in the app's own settings, keyed by project and transition name, so a Jira admin can change the list on an admin page and the validator reads the new list straight away. A rule for all projects can sit behind the project-specific ones.

The validator treats a field as empty when it is missing, null, an empty string, an empty array, or rich text with nothing but blank space. The error message names exactly which fields are missing. Everything the app stores is removed when it is uninstalled.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Required on Transition for Jira.

  • One workflow validator: "Required fields on transition"
  • Rules per project and transition, plus a rule that covers every project
  • Rules edited on a Jira admin page, no workflow edit needed to change them
  • Empty means missing, null, blank string, empty array or blank rich text
  • Block message lists the missing fields by name
  • Stored rules removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
