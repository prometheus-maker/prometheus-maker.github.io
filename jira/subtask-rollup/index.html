Subtask Rollup for Jira

Sum, highest, lowest or average a child field onto the parent issue.

A number field on the parent calculated from its children's chosen number field, refreshed when a child changes and reconciled hourly.

What it does

Parents never show the size of the work underneath them. Story points sit on sub-tasks, estimates sit on children, and the total is added up by hand or kept in a spreadsheet that is out of date by the next grooming session.

Subtask Rollup for Jira adds one number field, "Child rollup", whose value is calculated from a parent's children. An admin picks the source number field and the calculation - sum, highest, lowest, average, or a count of children that have a value - and how many decimals to keep. The field then behaves like any other number field: it sorts, filters and appears in JQL.

The value is recomputed when a child issue changes, through Jira's issue-updated event, which reads the changed issue's parent and recalculates it. An hourly job walks the rest of the site in steps of 25 issues so drift is corrected, taking the 1000 oldest non-done standard issues and rebuilding that queue daily. A value is only written when it differs from what the field already holds.

The field reads at most 500 children per parent and shows when a parent has more. Configuration needs the Administer Jira permission; other users see the value read-only with a Refresh button. Field settings, the queue and the run log are removed on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under the custom field (add it to a screen in Jira settings → Issues → Screens).

  • One number field calculated from a parent's children
  • Sum, highest, lowest, average, or a count of children with a value
  • Decimals from zero to two
  • Recalculated when a child issue changes, and hourly for up to 1000 issues
  • Written only when the value changes
  • Up to 500 children read per parent, with a notice when there are more
  • Admin-only configuration; read-only value and a Refresh button for everyone else

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
