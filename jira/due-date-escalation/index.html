Due Date Escalation

Escalate overdue Jira issues to their manager automatically.

Write rules for overdue issues: comment with a mention, raise priority or hand the issue to the manager, once per issue.

What it does

A due date only turns red for whoever happens to look at the issue, so overdue work drifts until someone complains. By then the reason is gone and the ticket is a week older.

Due Date Escalation lets an administrator write rules per project: how many days overdue (1 to 365), who the manager is, and what should happen - a comment with a mention, a priority change, a reassignment to the manager, or all three. The comment text is written in the rule, and the manager is mentioned in it, so Jira notifies the person directly.

A preview lists the issues that match a rule before anything is applied. An hourly trigger then works through the matches: at most 10 issues per rule per run, with the rest waiting for the next hour. Each issue is escalated once per rule, tracked in storage for 90 days, so reopening a ticket does not spam the thread; a failed action is not marked as seen and is retried.

Rules are limited to 50, and each escalation is listed on the page with what was done. The scheduled run uses the app identity while Run now uses the admin who pressed it. No email is sent: the notification is the mention in the comment. All rules and seen keys are removed on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Due Date Escalation.

  • Rules per project with an overdue threshold from 1 to 365 days
  • Actions: comment with a manager mention, priority change, reassignment to the manager
  • Preview of matching issues before applying a rule
  • Hourly run, at most 10 issues per rule per run
  • Each issue escalated once per rule, remembered for 90 days; failed actions are retried
  • Recent escalations listed on the page
  • Up to 50 rules; all stored data removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
