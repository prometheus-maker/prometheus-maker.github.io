Bulk Clone for Jira

Clone many Jira issues at once, with their subtasks, links and attachments.

Pick issues with JQL, preview how many issues, subtasks, links and attachments the clone will create, then run it as one job into a target project. Each copy keeps a link back to its source.

What it does

Every release, audit or recurring maintenance window starts with the same set of issues. Copying forty of them by hand means forty clone dialogs, and the subtasks, links and attachments are usually lost along the way.

Bulk Clone takes a JQL query, runs it, and shows a pre-flight count: how many issues match, how many subtasks, links and attachments they carry, and what the clone will add up to. You choose the target project and which fields to copy, then start the job.

Work runs in batches on a scheduled trigger, so a few hundred issues are cloned without keeping a tab open, and the page shows progress as it happens. Each cloned issue gets a "Relates" link to the original, so the pair stays traceable. The result table lists every issue as copied, skipped or failed, with the reason for each failure — a partial run is visible, not silent.

The app uses the permissions of the user who starts the job: if you cannot create an issue in the target project, neither can the clone.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under the Apps menu in the top bar → Bulk Clone for Jira.

  • Source selection by JQL, with a pre-flight count before anything is created
  • Copies subtasks, issue links and attachments according to what you tick
  • Every clone gets a "Relates" link back to its source issue
  • Batched jobs on a scheduled trigger, for hundreds of issues without an open tab
  • Per-issue result table: copied, skipped or failed, with reasons
  • Choose the target project and the fields to carry over

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
