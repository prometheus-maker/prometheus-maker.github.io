Label Sync Across Projects

Merge label variants across projects, with a dry run first.

Find near-duplicate labels, approve the mapping, preview the change per project, then merge them in batches.

What it does

One team labels issues backend, another Back-End, a third back_end. Every filter and report that counts by label is wrong, and Jira has no rename or merge for labels at all.

Label Sync reads the site's labels and groups the ones that collapse to the same key once case, spaces, underscores and hyphens are ignored. For each group it proposes a target - the spelling with the most issues in the source project - and lists the variants to merge into it, with the reason: trim, case or separator. You approve, edit or remove each mapping; nothing is applied from a suggestion alone.

Before any change you run a dry run against the target projects you pick. It counts the issues carrying each source label in each project, in batches of 40, and lists anything it could not count. Apply is refused unless the current mapping matches the dry run exactly, so a mapping approved after the preview cannot slip through unseen.

The job then searches issue by issue and rewrites the issue's full label array - the source label is removed, the target added, and case duplicates collapsed - with one search page and up to 50 updates per invocation. A five-minute trigger continues the job until every issue is done, the page shows progress, and failures are listed per issue key; deleted issues are skipped and reported. The mapping and job state are in Forge storage, the page is admin-only, and everything is deleted on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Label Sync Across Projects.

  • Near-duplicate detection across the whole site by case, separator and spaces
  • Suggested target per group, based on issue counts in the source project
  • Appoint, edit or drop each mapping before anything runs
  • Dry run per target project with issue counts per label
  • Apply refused unless the mapping matches the last dry run
  • Rewrites the issue's label array, up to 50 issues per batch, run to the end by a five-minute trigger
  • Admin-only; mapping and job state removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
