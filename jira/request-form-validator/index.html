Request Form Validator

Catch incomplete portal requests before an agent starts on them.

Check each new request against rules you write, comment with what is missing, and optionally block a transition until it passes.

What it does

A portal request arrives with an empty description, a serial number that does not match anything, or a date in the past, and the agent finds out after picking it up. Jira's own required fields do not cover the checks teams actually need.

Request Form Validator checks each new request in one service project against rules you write in the admin page. A rule names a field and one of seven operators: required, minimum length, maximum length, a regular expression, one of a list of values, a number range, or a date after today. You give each rule your own message or keep the generated one, switch it off without deleting it, and reorder the list.

When a request fails, the app adds the label `invalid-request` and posts a public comment on the request listing what is missing - up to eight items - so the requester can reply in the portal with the details. When a later check passes and the label is present, the label is removed. A Re-check button runs the rules again on any issue key after the request has been corrected.

Enforcement is optional. Add the app's "Request form complete" validator to the workflow transition that starts work, switch on Block transitions, and that transition is refused while the last stored check for the issue failed, with the first missing item in the error. The validator reads the last check the app made, not the live form, so a Re-check after fixing is what clears the way. The admin page keeps the last 200 checks with pass or fail counts, and settings, rules and check rows are removed on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Request Form Validator.

  • Seven rule types: required, min and max length, pattern, one of, number range, date after today
  • One project and its request type field; rules run on issue creation
  • Public comment listing up to eight missing items, written for the requester
  • `invalid-request` label added on failure and removed when a check passes
  • Optional workflow validator that blocks a transition after a failed check
  • Re-check any issue by key after it is fixed
  • Last 200 checks and pass or fail counts; all data removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
