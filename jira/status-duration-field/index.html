Days in Status for Jira

A sortable number of days each issue has sat in its current status.

Days in status as a number field rebuilt from the changelog hourly and on every transition, so stale issues sort and filter in JQL.

What it does

Jira shows where an issue is, not how long it has been there. An aging review means opening the history tab issue by issue, and the number nobody can sort on is the one that matters: how long has this been sitting.

Days in Status for Jira writes that number into a number custom field. It reads the issue changelog, finds the newest status change and stores the whole days since then. Because the value is a number, JQL works on it: cf[fieldId] > 7 finds work sitting too long, ORDER BY sorts it, and "Days in status" is EMPTY finds issues never calculated.

An hourly job refreshes 25 issues per run, walking a queue of up to 1,000 issues that is rebuilt every 24 hours, and a transition event refreshes an issue as soon as its status changes. A value is written only when it differs from the stored one, so an idle site is not written to every hour.

The field must be added to your screens and issue layout. The app learns the field id the first time an issue is opened with the field on it; until then it stores values but cannot write them. State is kept in storage and removed on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under the custom field (add it to a screen in Jira settings → Issues → Screens).

  • A number custom field, whole days in the current status
  • Calculated from the newest status change in the changelog
  • Hourly refresh of 25 issues per run, queue of 1,000, plus immediate refresh on transition
  • Values written only when they change
  • Works in JQL: compare, sort and find empty values
  • Field and issue views included, with a manual Refresh
  • Stored state removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
