Dependency Map for Jira

See what blocks what in an epic, before the plan breaks.

A matrix of Blocks links for one epic, the longest blocking chain, any cycles, and a CSV of the edges.

What it does

An epic's issues are not a flat list: one has to land before another, two block each other by mistake, and the chain that decides the delivery date runs through five tickets nobody looked at together. Someone reads the links one issue at a time, and the chain that matters stays invisible.

Dependency Map reads one epic and the issues under it - through the Epic Link field when the site has one, otherwise through the parent field - up to 150 issues, with a warning when the epic is larger. It keeps the Blocks links between those issues and ignores links to anything outside the epic, though it counts the other link types it found.

The result is a matrix: a row per issue, a column per issue, `>` where the row blocks the column and `<` where it is blocked by it. Two further views follow. The longest blocking chain lists the sequence of issues that has to happen in order, with cycle members left out. The cycle list shows every blocking loop found, up to ten, because a loop in a dependency plan is always a mistake to fix.

The edges export as CSV in the format `from_key,from_summary,to_key,to_summary,relation`, shown in a read-only box to copy - UI Kit has no file download. The matrix reads best on an epic of twenty or so issues; on a larger one the chain, the cycle list and the CSV carry the answer. Everything is read-only, the only scope is `read:jira-work`, and no data is stored between views.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under the Apps menu in the top bar → Dependency Map for Jira.

  • Epic scope via Epic Link or parent field, up to 150 issues
  • Blocks-only matrix with `>` and `<` for direction
  • Longest blocking chain with cycle members excluded
  • Cycle detection listing up to ten loops and the total
  • Count of non-blocking link types found in the epic
  • CSV export of every blocking edge
  • Read-only, one Jira scope, no storage

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
