Request Type Clone for Jira Service Management

Clone a request type to another service desk and see exactly what is left to set up.

Creates a request type in another service desk with the same name, description and group, then diffs the fields and shows a checklist of what still needs doing.

What it does

A new service desk usually starts from an old one, and request types are rebuilt by hand: same name, same description, same group, and then the portal fields, which the API cannot copy.

Request Type Clone creates the type in the target desk with the name, description, group and icon, then compares the source and target field lists and shows a checklist of what a person still has to configure - portal fields, required flags, the issue type and workflow association. It does not pretend those are done: it names them.

A preselected target desk makes the common case one click, and the last 50 clones are kept as a history so a reviewer can see what was created and from where. Everything is removed on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Request Type Clone for Jira Service Management.

  • Creates a request type in another service desk with name, description, group and icon
  • Compares the field lists and shows a checklist of what the API cannot copy
  • A preselected target desk for repeated clones
  • A history of the last 50 clones
  • Admin page, no workflow editing
  • Stored settings and history removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
