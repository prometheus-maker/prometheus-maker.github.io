Attachment Cleanup for Jira

Find oversized and unattached Jira attachments, then delete them safely.

Scan Jira attachments by size, age and file type, flag files no comment or description mentions, and delete only what you select, after a dry run.

What it does

Attachments are the quiet cost of a long-lived Jira site: screen recordings, duplicate exports, log files nobody opens again. Jira shows attachment size only one issue at a time, and has no notion of a file that nothing refers to any more.

Attachment Cleanup scans a selection of issues and lists every attachment with its size, date, type and issue, plus a flag for files whose name appears in no description or comment on that issue. You filter by a JQL query, a minimum size, a minimum age and a file type prefix, so the scan can be narrowed to the big old screen recordings and skip everything else.

The page totals what it found: number of files, total size, and how much of that total is flagged as unattached. Nothing is deleted until you tick rows and confirm. The delete job then works through the selection in batches of fifty and reports every file as removed, already gone, or refused.

The unattached flag is a heuristic based on the file name appearing in the issue text, and the page says so: check the file, the issue and the size in the table before you confirm a delete.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Attachment Cleanup for Jira.

  • Scan by JQL, minimum size in MB, minimum age in days and MIME type prefix
  • One table of every matching attachment: size, date, type, issue
  • Flag for files whose name appears in no description or comment
  • Totals for file count, size and flagged size
  • Select rows and delete, up to 500 files per job, in batches of 50
  • Per-file result after the job: removed, already gone or refused

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
