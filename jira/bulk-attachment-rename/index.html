Bulk Attachment Rename

Rename Jira attachments in bulk with a naming pattern.

Pick issues by JQL, set a pattern like {issue}-{index}-{filename}, preview every new name and rename in safe batches.

What it does

Attachments named "Screenshot 2026-11-15 at 10.14.22.png" make tickets hard to read, and renaming them by hand across a project is an afternoon of downloading and uploading files.

Bulk Attachment Rename takes a JQL query, a naming pattern and nothing else. The pattern uses the issue key, the 1-based position of the file on the issue, the original name without its extension and the extension itself - for example {issue}-{index}-{filename}{ext}. Illegal filename characters are replaced with a dash and names are trimmed to 200 characters. A preview lists every old and new name before anything changes.

Renames run three attachments per call, with the admin page continuing every two seconds, so the work survives the 25-second limit on a Forge invocation. Each file is downloaded, uploaded under its new name, and only then is the old attachment deleted. Files over 10 MB, files whose name already matches and files that have disappeared are skipped and listed. Each renamed file gets a new attachment id, so links that point at the old id stop working; the preview is there to catch that before it happens.

Only Jira administrators can open the page. The active job, the last result and the settings are kept in storage and removed on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Bulk Attachment Rename.

  • Issues chosen by JQL, not by hand
  • Pattern tokens for issue key, position, original name and extension, with illegal characters replaced and names capped at 200 characters
  • Preview of up to 100 old and new names before any change
  • Three renames per call, continuing on the page until done
  • Files over 10 MB, unchanged names and missing files skipped and listed
  • Upload-before-delete, with a new attachment id per renamed file
  • Admin permission required; stored job data removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
