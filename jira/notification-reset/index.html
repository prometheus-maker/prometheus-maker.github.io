Notification Reset for Jira

Bulk reset watchers and scheme recipients for users who ask.

Collect reset requests from a JQL filter and clear a user's issue watchers and Single User scheme entries in one dry-run-first job.

What it does

"Please reset my notifications" is a request an administrator answers by clicking through issue after issue and scheme after scheme, with no list of what the user actually carries.

Notification Reset reads the requests from a JQL filter - by default labels = notification-reset AND resolution = Unresolved, and you can change it on the page. It returns one row per distinct reporter with a Reset button. A preview then counts, before anything is changed, how many issue watchers and how many Single User entries in notification schemes that person holds, and states the totals in a dry-run line.

The reset itself runs as a background job: a five-minute scheduled function removes watchers 50 at a time and rewrites one scheme per step, so a user watching a thousand issues does not hit a timeout. Up to 200 users can be queued in one job. Every reset is recorded per account, with the watcher keys and scheme entries it removed, and the Restore action puts them back - once per event and user, skipping issues deleted in the meantime. A 403 from the scheme API stops the job with a clear message instead of half-finished work.

It changes only two things: issue watchers for the selected users and their Single User entries in notification schemes. Personal notification preferences are left exactly as each user set them, other recipients on the same scheme events are untouched, and stored job data, reset records and the scheme cache are removed on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Notification Reset for Jira.

  • Requests collected from your JQL filter, one row per reporter
  • Dry-run preview of watcher and scheme entries before any change
  • Reset job bounded to 200 users, 50 watcher removals per step
  • One scheme rewritten per job step, so large schemes do not time out
  • Reset records per user with one-click Restore
  • Deleted issues reported as skipped rather than failing the job
  • Personal notification preferences never touched; stored data removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
