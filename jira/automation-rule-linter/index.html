Automation Rule Linter

Find automation rules that loop, duplicate or fight each other.

Paste your Jira automation rule exports and get a ranked list of loops, duplicates and rules that write the same field.

What it does

A rule that edits the issue which triggered it can fire forever, and two rules writing the same field on the same event overwrite each other without an error. Neither shows up as an error in Jira, and reading a hundred rules by hand does not find them reliably.

Automation Rule Linter takes the JSON export of your rules, pasted into one box, and checks five things: a rule whose action matches its own trigger, a rule with no conditions at all, two rules with the same shape, a disabled rule covered by an enabled one, and two rules that write the same field on the same event. Each finding names the rules involved and is ranked HIGH, MEDIUM or LOW, with the rule names and ids in the table.

The app caps a paste at 200 rules and 2 MB of text and says when the input is larger. It keeps the last run so you can return to the findings, and drops that on uninstall.

Jira Automation has no API that apps can read, which is why rules are pasted rather than fetched. Apart from a permission check, the app reads nothing from Jira and writes nothing to it. The checks are static: they read the rule structure and do not run or simulate a rule.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Automation Rule Linter.

  • Five checks: self-triggering loop, no conditions, duplicate, disabled covered by enabled, same field on the same event
  • Findings ranked HIGH, MEDIUM and LOW with the rule names
  • One paste for a whole rule export
  • At most 200 rules and 2 MB of text per run, stated in the app
  • Last result kept and restored on return
  • Admin permission check before the page is usable
  • Nothing written to Jira; stored result removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
