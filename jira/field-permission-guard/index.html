Field Permission Guard for Jira

Keep sensitive field values out of the wrong hands, and put back any that are changed.

Per-project field policies that restore unauthorised edits, keep an audit log, and store a guarded text field's value where only allowed users can read it.

What it does

Jira's field-level permissions either do not exist for most fields or apply to every project at once. A salary reference, a customer identifier or a legal note ends up editable by anyone who can edit the issue.

Field Permission Guard adds policies per project or for the whole site. When an issue is created or updated, it compares lockable fields - text and labels - with the policy, restores any value changed by someone not allowed to change it, and records the action in an audit log the admin page shows. Administrators are recognised by their membership of the standard administrator groups, and an empty allow list means administrators only.

It also adds a Guarded Text custom field. The value is kept in the app's own storage and the issue holds only a token; a policy on that field decides who may see and edit it, and with no policy only administrators can. Uninstalling removes every stored policy, value and audit entry.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under the custom field (add it to a screen in Jira settings → Issues → Screens).

  • Field policies per project or site-wide, with project policies taking precedence
  • Unauthorised changes are restored and written to an audit log
  • Audit log on the admin page, with who changed what and when
  • Guarded Text custom field whose value stays in app storage, not on the issue
  • Standard administrator groups recognised out of the box
  • Gate on the create screen: Guarded Text is set on existing issues
  • All stored policies, values and logs removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
