Request Type Field Audit

See which request type fields no portal form uses.

Audit every JSM portal: which fields its request types show, which are hidden, and which no form uses at all. Export to CSV.

What it does

Portal settings show one request type at a time, so nobody notices the fields that stopped being used years ago, or the ones collected on one form and forgotten on the others.

Request Type Field Audit scans your service desks - all of them, or the ones you select - and reads the field list of every request type, including hidden request types. It builds one table of every field with its request type, required flag and visibility, then adds three views on top: fields that appear on some request types of a portal but not all (with "used on X of Y"), fields configured but never visible to customers, and custom fields that no request type in that portal references at all.

The scan runs in batches, one service desk and at most 40 request types per step, with the admin page calling it until done, so a site with many portals does not time out. Results are stored in shards of 200 rows and the table pages through them; the current view exports to CSV with one click. The summary keeps the portal, request type, used, unused and hidden counts plus the time of the last run.

The app only reads. It cannot see field schemes or screens, so "unused" means no request type field references the custom field in that portal - not that the field is safe to delete everywhere. Running an audit requires the Administer Jira permission, and all stored rows, the field list and the index are deleted on uninstall.

Install

Where to install it: Jira Cloud, from the Atlassian Marketplace.

Open Apps → Manage your apps in Jira, choose Find new apps, search for the app name and click Install.

What you can do with it

You find it under Jira settings → Apps → Request Type Field Audit.

  • Every service desk, or only the portals you pick
  • One row per field per request type: required and visible flags
  • Views for unused custom fields, hidden fields, and gaps across request types
  • Gap rows labelled "used on X of Y" request types
  • Batched scan of 40 request types per step, results in 200-row shards
  • CSV export of the current filtered view
  • Read-only; all stored data removed on uninstall

Your data

The app runs on Atlassian Forge inside your own site. Settings and any cached results are stored in Forge storage, which belongs to your site; nothing is copied to another service, and nothing is read beyond what the app needs to do its job. Removing the app removes what it stored. Details: privacy policy.
