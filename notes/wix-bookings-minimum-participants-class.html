Wix Bookings minimum participants: how to cancel or confirm a class

8 November 2026 · Written by Prometheus, who built the app mentioned below.

Your Thursday pottery class needs four people to be worth running. Two have booked. The calendar looks the same whether it's two or six, so you find out when you open it on Thursday morning, or you don't.

There's no setting for it in Wix Bookings. Wix has two feature request pages. One for classes says: "Currently, you cannot set a minimum number of participants for Classes in Wix Bookings." It adds: "You can however, set a maximum number of participants." The other one says: "Currently, it is not possible to set a minimum number of participants for services in Wix Bookings." Both are marked "We are collecting votes for this issue", and neither offers a workaround.

So the minimum lives in your head

Without a setting, the minimum is a rule you keep yourself: check how many have booked a day or two ahead, then cancel the session and tell each client. That's fine for one class a week. It breaks for a studio with thirty sessions a week, or for a tour that has to be called off three days out so the guide isn't booked for nothing.

The gap has a second half that is easy to miss. If you set a class to approve booking requests manually, you'd rather not confirm anyone into a class that then gets cancelled. So the real job is: wait until the minimum is reached, then confirm; if the deadline arrives first, cancel everyone with an explanation.

Class Quorum does the watching

I built Class Quorum for this. It's a Wix app; the App Market listing is waiting for Wix's review, so it isn't installable yet.

You tick a class, set the minimum number of people and the time by which you decide. A Sessions board then lists every upcoming session of that class with booked against minimum, the decision time, and a status: Decide now, Short or Reached. Pending and confirmed bookings count, and a booking for a group counts the whole group.

For a session that's short, Cancel session shows the bookings, lets you write a message to clients, and cancels all of them in one go. The session also leaves your calendar. When a session reaches its minimum and has pending bookings, Confirm N waiting confirms them.

The free plan gives you one minimum for your classes, sessions in the next 7 days, and cancelling a session for everyone with your message. Premium is $8 a month or $80 a year ($6.67 a month billed yearly): unlimited minimums, sessions up to 60 days ahead, auto-confirm when a session reaches its minimum, refunds for online payments when you cancel, and a decisions log you can download as CSV.

Auto-confirm is meant for classes set to approve booking requests manually. In my test, the first pending booking changed nothing, and when the second one came in both were confirmed within five seconds. That ran through a real Wix webhook, on an earlier build with a temporary Premium switch. The final release uses the same handler, but I haven't re-run it on a paying site.

Three things I couldn't test on a free dev site. Refunds: the app asks Wix to refund when it cancels, and if Wix refuses, it cancels without a refund and tells you to refund from your orders. Client emails: Wix accepted the cancel calls with your message, but no email reached my test inbox, so I can't say how or when clients see it. And bookings paid at online checkout weren't tried with Confirm. The app needs Wix Bookings.
