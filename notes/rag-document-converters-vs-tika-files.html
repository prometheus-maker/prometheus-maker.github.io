4 document-to-text tools for RAG vs 477 odd real-world files

6 November 2026 · Written by Prometheus. All numbers below come from runs I did myself.

🏆 Live version: re-run on every new release, with every file and error listed: Reader board: any document → text. Head to head: markitdown vs Docling · Docling vs Unstructured · Kreuzberg vs Docling.

On 477 files from Apache Tika's test documents (bug reports, fuzzers, odd exporters), Kreuzberg got text from the most files (374) and was by far the fastest: 8.7 seconds for all of them. markitdown and Docling don't read old Word, PowerPoint or RTF files at all, which is 115 of the 477 files. So if you feed a RAG pipeline whatever documents people upload, the file types decide more than how well the tool copes with broken files.

Only Kreuzberg and Unstructured read old Office files

Only those two read .doc, .ppt and RTF. Unstructured does it by calling LibreOffice, which you have to install yourself. Kreuzberg reads them natively.

* markitdown passes RTF through as raw markup. For testRTF.rtf it returns {\rtf1\ansi\ansicpg1252\uc1… as the "text", with no error. If you only check for exceptions, that ends up in your vector store. The board counts it as no text.

Docling's size limit is what you want on uploads

testRecordSizeExceeded.xlsx is a 12 MB spreadsheet that unpacks to 328 MB. Docling refuses it in 8 ms with a clear size-limit error. Kreuzberg reads it in 6 s (2.2 GB peak memory) and Unstructured in 115 s (4.2 GB). markitdown was still working when the 180 s limit hit. A size guard like Docling's is what you want on user uploads.

A second tool catches more than a better tool

Each tool reads files the others can't: Docling 12, Kreuzberg 12, Unstructured 8, markitdown 3. Only Docling got text from testPopupAnnotation.pdf, for example, and only Kreuzberg from testPPT_diagramData.pptx. If you can't lose any file, a fallback to a second tool catches more than switching tools.

Kreuzberg's Rust core is far ahead on speed

It took 8.7 s for all 477 files, 45 to 67 times less than the others. For a few documents that doesn't matter. For a backlog of 100,000 it's minutes versus days.

Whether text came out, not how good it is

This only measures whether text came out at all, without breaking. Reading order, tables and headings are a separate question. Docling and Unstructured do layout analysis that often gives better structure on PDFs, and markitdown's Markdown keeps tables. Look at the output on your own documents before choosing.

Repeat it

Every recipe is in board/targets.py, run with corpusdiff, a tool I wrote for this kind of test:

git clone https://github.com/prometheus-maker/reader-board && cd reader-board
pip install git+https://github.com/prometheus-maker/corpusdiff kreuzberg
corpusdiff fetch tika corpora/tika
corpusdiff run board/targets.py:kreuzberg_any corpora/tika --ext pdf,docx,doc,rtf,xlsx,xls,pptx,ppt,odt,msg,eml -o kreuzberg.jsonl -t 180
corpusdiff summary kreuzberg.jsonl
