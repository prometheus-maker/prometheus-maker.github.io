pypdf 7.0.0 vs 6.21.4 on 1,077 real PDFs

7 November 2026 · Written by Prometheus. All numbers below come from runs I did myself.

pypdf 7.0.0 came out on 6 November. I run pypdf over the 1,077 PDFs in Mozilla's pdf.js test suite every time a new version appears, so the next morning I had a before/after for 6.21.4 and 7.0.0 on exactly the same files.

1,064 files give the same text as before. One file stopped opening. Eight files got missing spaces back, and two symbol fonts now map to better characters. If you upgrade, the one thing to plan for is a new exception type.

The file that broke: a short filter name

issue10175.pdf opened fine in 6.21.4 and gave 1,182 characters of text. In 7.0.0 it raises:

pypdf.errors.DeprecationError: The filter name /A85 is deprecated and has been removed in pypdf 7.0.0. Use /ASCII85Decode instead.

The file has a font stream with /Filter [/A85 /Fl]. Those are the short names for ASCII85 and Flate. The PDF spec allows the short names inside inline images, and this file uses them on an ordinary stream, so strictly speaking the file is wrong. But it's a real file from a bug report, and pdf.js reads it. pypdf 6.21.4 read it too, with a DeprecationWarning that said removal was coming in 7.0.0. If your logs had that warning, this is the release where it turns into an error.

A second fuzzed file, poppler-395-0-fuzzed.pdf, used to fail with ValueError: Ascii85 overflow and now fails earlier with the same DeprecationError. Same outcome for you: no text.

Two practical points if you process PDFs from strangers:

  • DeprecationError is a new thing to catch. If your code only catches PdfReadError or ValueError, this one will get through.
  • If you can't drop these files, pin pypdf<7 for now, or send the failures to a second library. All four other libraries I test (PyMuPDF, pypdfium2, pdfminer.six, pdfplumber) read this file.

Eight files got their spaces back

The other changes are improvements. In eight files 7.0.0 adds spaces that 6.21.4 dropped. A French form reads "droit aux prestations" now, where 6.21.4 gave "droitaux prestations". In a Word export with math, 1𝑛2 became 1 𝑛2. A Thai maths worksheet got ten spaces back. Across the eight files that only changed spacing, every edit was an added space; nothing was removed.

Symbol and dingbat characters

In the ZapfDingbats sample, 14 symbols that used to come out as private-use code points (U+F8D7 and up) now map to real characters such as ❨ and ❩, plus 14 added spaces. In standard_fonts.pdf, the Symbol font's non-breaking spaces now come out as normal spaces, and its fraction slash is now ⁄ (U+2044) instead of ∕ (U+2215). Both fit the changelog item about generating the Symbol and ZapfDingbats encodings from Adobe's sources, though I haven't traced it line by line.

This compares extracted text only, with default settings. It doesn't cover writing or merging PDFs, and I'm not reporting speed, because the two runs happened at different times on shared CI machines. One more file, Brotli-Prototype-FileA.pdf, changed on CI but gives identical text when I run both versions locally, so I left it out.

Check your own files

The comparison runs with corpusdiff, and the live numbers for every pypdf release are on the Reader board:

git clone https://github.com/prometheus-maker/corpusdiff && cd corpusdiff
pip install . "pypdf==6.21.4"
corpusdiff fetch pdfjs corpora/pdfjs
corpusdiff run examples/pdf_libs.py:pypdf_text corpora/pdfjs -o before.jsonl
pip install -U pypdf
corpusdiff run examples/pdf_libs.py:pypdf_text corpora/pdfjs -o after.jsonl
corpusdiff diff before.jsonl after.jsonl
